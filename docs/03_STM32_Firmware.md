# 3. STM32 firmware

Code: [`firmware/src/main.c`](../firmware/src/main.c). PlatformIO project with the **STM32Cube** framework (ST HAL), without STM32duino. USB uses the ST USB Device library (V2.11.6, copied into `firmware/src/usb`, license in `src/usb/LICENSE.md`).

Since version 2.0.0 the firmware **does not oversample**: it sends every ADC sample (12 bits, 200 kS/s) together with the laser state at that sample, and the interface averages the chosen number of samples (see [Interface](04_Interface.md)). This way the firmware never changes and the oversampling can be changed without reflashing the board.

> Why STM32duino was dropped: its USB CDC topped out at ~190 kB/s on the Black Pill. With the ST stack, long transfers and double buffering, the same hardware reached ~1.1 MB/s without losses (test of 2026-11-05). The 2.0.0 stream is ~550 kB/s, half of that.

## PlatformIO configuration

```ini
[env:blackpill_f401cc]
platform = ststm32
board = blackpill_f401cc
framework = stm32cube
upload_protocol = stlink
build_flags =
    -O2
    -Wall
    -I src/usb/Core/Inc
    -I src/usb/Class/CDC/Inc
```

## Flashing

1. Connect the ST-Link to the Black Pill SWD pins ([wiring](02_Hardware_and_Wiring.md#st-link-programmer)).
2. In VS Code, open the `firmware/` folder with PlatformIO.
3. Click **Upload** (or run `pio run -t upload` inside `firmware/`). The first time, PlatformIO downloads the `framework-stm32cubef4` package.
4. Disconnect the ST-Link (optional) and connect the board over USB-C. A COM port "USB Serial Device" (VID 0483, PID 5740) should appear.

Alternatively, flash the prebuilt `binarios/soi_firmware_vX.Y.Z.bin` at address `0x08000000` with STM32CubeProgrammer.

## Clocks

| Domain | Frequency | Source |
|---|---|---|
| HSE (crystal) | 25 MHz | WeAct board |
| SYSCLK / HCLK | 84 MHz | Main PLL (25 MHz / 25 × 336 / 4) |
| APB1 timers (TIM3, TIM4) | 84 MHz | APB1 × 2 |
| APB2 timer (TIM1) | 84 MHz | APB2 |
| ADC | 21 MHz | PCLK2 / 4 |
| PLLI2S → I2SCLK | 76.8 MHz | 25 MHz / **M=25** × **N=384** / **R=5** |
| USB | 48 MHz | Main PLL |

The HAL leaves PLLI2SM = 0 on this chip. That is why the firmware writes **M = 25** directly into `RCC->PLLI2SCFGR`.

## Peripherals

### Laser (TIM1 + TIM4)

| Parameter | Value |
|---|---|
| PWM carrier | TIM1_CH1 on **PA8**, **5 kHz** |
| Power | Command `P`, 0 to 100 %, 0.1 % steps. The value is written straight to CCR1 (no preload), so it takes effect immediately. |
| Modulation | 50 % square wave generated by the **TIM4** interrupt (priority 0, the highest) |
| Modulation range | **0.1 to 5000 Hz**. `F0` = continuous laser |
| Modulation resolution | < 100 Hz: half-period in whole µs. ≥ 100 Hz: 95 ns ticks (84 MHz / 8). These are the same roundings as in 1.0.0, and the interface reproduces them (`actual_mod_freq`). |
| Sync | **PB0** = modulation state (1 = on) |
| Initial state | 5 Hz, 0.4 % |

> Above ~1 kHz each half-period contains few cycles of the 5 kHz carrier (2.5 cycles at 1 kHz). For high modulation frequencies, prefer PWM = 100 %, which keeps the laser continuously on during the on half-period.

### Optical channel: ADC1 + TIM3 + DMA2

| Parameter | Value |
|---|---|
| Input | **PA0** (ADC1_IN0), 12 bits, sampling time 84 cycles (4 µs) |
| Trigger | **TIM3** TRGO at **200 kHz** (84 MHz / 420) |
| Transfer | **DMA2 Stream0 Channel 0**, circular, interrupt every half window of 512 samples (2.56 ms, priority 1) |
| Oversampling | **None in the firmware.** Each sample is sent raw to the PC (12 bits, 0 to 4095) |
| Output rate | **200,000 samples/s** (400 kB/s) |
| Reference | The laser state is recorded on the same sample grid as the ADC (bit 15 of each word) |
| Buffer | Ring of 8192 samples (41 ms). If the PC falls behind, the oldest samples are dropped and the jump in SEQ tells the interface. |

Parameters at the top of `main.c`: `ADC_RATE_HZ` and `LASER_PWM_HZ`. A `_Static_assert` requires the ADC rate to divide 84 MHz. **If you change `ADC_RATE_HZ`, also change `RAW_FS` in the Python code.**

### Acoustic channel: I2S2 + DMA1

| Parameter | Value |
|---|---|
| Peripheral | SPI2 in **I2S master RX** mode, **Philips** standard |
| Pins | PB13 = CK, PB12 = WS, PB15 = SD (AF5) |
| Format | **24-bit** data in a 64-bit frame (2 × 32), **left** slot only |
| Rate | **Exactly 48 kHz**: 76.8 MHz / (64 × 25), with I2SDIV = 12 and ODD = 1. (Up to 1.0.0 it was 31,994.05 Hz, −186 ppm.) |
| BCLK | 3.072 MHz |
| Transfer | **DMA1 Stream3 Channel 0**, circular, interrupt every 256 frames (5.3 ms, priority 2) |
| Buffer | Ring of 2048 samples (43 ms). If the PC falls behind, the oldest samples are overwritten (the sequence number shows the gap). |

### Phase synchronization between the two channels

When the frequency changes (command `F`), TIM4 is configured and left **stopped**. At the **next I2S DMA interrupt**, the firmware waits, with interrupts masked, for the DMA to start a new I2S frame and starts TIM4 at that instant (maximum wait ~40 µs). The number of that frame, computed from the DMA `NDTR`, is sent to the PC in the **modulation marker**. This keeps interrupt latency out of the phase. The INMP441 lock-in uses that number as its phase origin, so the OPT101 and INMP441 phases share the same reference (laser rising edge).

> Up to the 2026-10-23 version, the marker assumed the start happened at the half-buffer boundary. In practice it happened ~3 frames (≈ 100 µs) later, because the ISR first copies the 256 samples. Microphone calibrations made before that date include this delay in `td` and should be redone.

### Interrupt priorities

| IRQ | Priority | Reason |
|---|---|---|
| TIM4 (modulation) | 0 | Jitter-free laser edge |
| DMA2 Stream0 (ADC) | 1 | — |
| DMA1 Stream3 (I2S) | 2 | — |
| USB (OTG_FS) | 3 | Below everything that keeps time |

Copying the audio ring in the main loop masks only priorities ≥ 2 (`BASEPRI`), not all interrupts. This way the laser edge (TIM4) is not delayed during the copy.

## USB protocol (STM32 → PC)

A single byte stream over USB CDC (the baud rate is ignored). The main loop builds packets in one of two 6 KB buffers while the other is being sent. The optical channel has priority: losing optical samples disturbs the lock-in PLL. Everything is little-endian, and the CRC is CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF) over the bytes between the 4-byte header and the CRC itself.

> The protocol changed in 2.0.0 (the 5-byte `55 AA` frames no longer exist). Firmware and interface must have the same major version.

**Optical packet (up to 1036 bytes)**, ≈390 per second (≈400 kB/s):

| Bytes | Content |
|---|---|
| 0–3 | `A5 5A 4F 50` (“OP”) |
| 4–7 | SEQ: absolute index of the 1st sample since start (uint32). A jump means lost samples. |
| 8–9 | N samples (uint16, 64 to 512) |
| 10 … 10+2N−1 | N uint16 words: bits 0–11 = ADC, bit 15 = laser (1 = on), bits 12–14 = 0 |
| last 2 | CRC16 |

**Audio packet (780 bytes)**, 187.5 per second (≈146 kB/s):

| Bytes | Content |
|---|---|
| 0–3 | `A5 5A 49 32` (“I2”) |
| 4–7 | SEQ: index of the 1st sample (uint32) |
| 8–9 | N samples (uint16, = 256) |
| 10 … 10+3N−1 | Signed 24-bit PCM samples |
| last 2 | CRC16 |

**Modulation marker (10 bytes)**, sent at every modulation start:

| Bytes | Content |
|---|---|
| 0–3 | `A5 5A 4D 4B` (“MK”) |
| 4–7 | SEQ of the I2S sample at the rising edge (uint32) |
| 8–9 | CRC16 of bytes 4–7 |

Total bandwidth ≈ 550 kB/s, half of what USB FS delivered in the test. With the port closed on the PC (DTR off), the firmware discards the data and does not hang.

## Commands (PC → STM32)

ASCII text terminated by `\n` (`\r` is ignored). Up to 23 characters. Invalid commands are silently ignored.

| Command | Range | Effect |
|---|---|---|
| `F<hz>` | `0` or `0.1`–`5000` | Modulation frequency. `F0` = continuous. Restarts the square wave and sends a new marker. |
| `P<pct>` | `0`–`100` | Power (PWM duty), 0.1 % resolution. |

Examples: `F5\n`, `F137.5\n`, `P40\n`. The interface sends `F` and `P` every time it connects.
